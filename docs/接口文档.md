## 2. 数据模型与表结构

### 2.1 候选人（candidate）——名单与面试状态

| 列 | 类型 | 说明 |
|---|---|---|
| student_no | VARCHAR(10) PK | 学号：恰好 10 位数字，名单/数据库唯一键 |
| name | VARCHAR(64) | 姓名（汉字链，可含 ·）；导入与手动改名均校验 |
| status | VARCHAR(16) | PENDING=未面试 / INTERVIEWING=面试中 / FINISHED=已结束面试 |
| finished_at | TIMESTAMP | 面试完成时间；未完成 NULL |
| imported_at / updated_at | TIMESTAMP | 首次导入 / 最近更新（自动维护） |

状态机：`PENDING --开始面试--> INTERVIEWING --结束评分(n≥1)--> FINISHED`；INTERVIEWING
可跨进程暂存续面、全局唯一；FINISHED 不可重开（补录/附加除外）；`resetAll()` 全部回到
PENDING（名单保留）；`resetEverything()` 删除整库（见 §8.6）。

### 2.2 四维评分（score）——一条记录 = 一次完整四维录入（v2）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGINT 自增 PK | 撤销/删除引用锚点 |
| student_no | VARCHAR(10)（逻辑外键→candidate） | 所属候选人 |
| r | DECIMAL(6,2) | 责任心，CHECK 0~25，两位小数 |
| t | DECIMAL(6,2) | 时间管理能力，CHECK 0~25 |
| s | DECIMAL(6,2) | 学生工作能力，CHECK 0~25 |
| f | DECIMAL(6,2) | 部门契合度，CHECK 0~25 |
| created_at | TIMESTAMP | 录入时间 |

一期旧库（单列 `score.points` 标量）打开时自动迁移：旧表改名归档 `score_legacy_v1`
（连同 `op_log_legacy_v1`），再建新表；候选人名单保留（面试状态重置为未面试，见 §8.7）；
**旧评分不换算进四维**（留档请用一期导出 CSV，取舍详见 §8.7）。

### 2.3 附加分（bonus）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGINT 自增 PK | 撤销引用锚点 |
| student_no | VARCHAR(10)（逻辑外键→candidate） | 所属候选人 |
| amount | DECIMAL(6,2) | 单笔 0~10（新库 CHECK；旧库迁移后 DB CHECK 仍宽容 0~100，由服务端统一强校验 0~10） |
| reason | VARCHAR(200) | 加分原因（必填、去空白非空、≤200 字） |
| created_at | TIMESTAMP | 记录时间 |

### 2.4 操作日志（op_log）——撤销功能的数据源（v2）

| 列 | 类型 | 说明 |
|---|---|---|
| seq | BIGINT 自增 PK | LIFO 撤销锚点 |
| student_no | VARCHAR(10) | 被操作候选人 |
| op_type | VARCHAR(12) | ADD_SCORE / DEL_SCORE / ADD_BONUS |
| ref_id | BIGINT | 被操作行 id |
| r / t / s / f | DECIMAL(6,2) 可空 | 四维评分快照（ADD/DEL_SCORE 用） |
| amount | DECIMAL(6,2) 可空 | 附加分快照（ADD_BONUS 用） |
| reason | VARCHAR(200) 可空 | 附加分原因快照 |
| occurred_at | TIMESTAMP | 被操作行自身录入时间快照（撤销删除时还原用） |
| created_at | TIMESTAMP | 日志时间 |

日志持久化，**支持深度 = 日志条数（到日志起点）**；`resetAll()` 清空日志，
因此撤销不能跨初始化（详见 §8.4）。

### 2.5 名单与数据库一致性 / 级联

“名单”与“数据库名单”是同一张 candidate 表的两种视图：导入文件 = 批量来源（学号幂等
upsert）；名单管理（新增/改名/改学号/删除）= 单条维护。改学号/删除自动级联
score/bonus/op_log（改号 = 三表 `student_no` UPDATE + 主表 UPDATE；删除 = 三表 DELETE +
主表 DELETE）。**面试中（INTERVIEWING）禁止改号与删除**；FINISHED 允许（调用方二次确认）。

### 2.6 存储位置与配置

- H2 文件库 `data/scoring.mv.db`；URL 解析：`-Dscoring.db.url=…` → `SCORING_DB_URL` →
  默认 `jdbc:h2:file:data/scoring`（相对启动目录；父目录由入口自动创建）。
- 依赖：H2 2.2.224（纯 Java）；Apache POI 5.2.5 系（纯 Java，xlsx/xls 读取，体积约 +15MB，
  不影响跨平台打包）；openjfx-17（仅 GUI）。选型理由沿用一期（纯 Java 无原生库，跨平台无坑；
  对比 SQLite-JDBC 的原生库打包风险而弃用）。

## 3. 最终分计算规则（四维）

### 3.1 平均口径（每维度独立，与一期“去极值”精神一致）

```
对某维度 X（r/t/s/f），设 n = 该候选人评分记录条数（每条记录必含四维，各维 n 相同）：
  n ≥ 3：X 平均 = 去掉该维度一个最高、一个最低后，剩余 n-2 个值之和 / (n-2)
  n = 1～2：X 平均 = 各值之和 / n    （结束面试时需二次确认）
  n = 0：不允许结束面试（提示先录入至少 1 条完整记录）
每个维度的极值独立判定（不同维度的最高/最低可来自不同记录）；
每维平均舍入两位小数（HALF_UP）。
```

### 3.2 总分结构

```
四维合计 = 责任心平均 + 时间管理能力平均 + 学生工作能力平均 + 部门契合度平均   （每维 ≤25 → 合计 ≤100）
最终分 = 四维合计 + Σ附加分      （单笔 ≤10、可多笔、无总上限：基础 100 + 附加）
```

最终分不落库，由明细动态计算（任何写操作后重算，杜绝“改了分忘了重算”）。

### 3.3 例子

| 记录 | 责任心 r | 时间管理 t | 学生工作 s | 部门契合 f |
|---|---|---|---|---|
| 1 | 20 | 18 | 22 | 16 |
| 2 | 24 | 10 | 12 | 20 |
| 3 | 16 | 20 | 25 | 10 |
| 4 | 20 | 16 | 14 | 22 |

n=4：r 去 16/24 → 20；t 去 10/20 → 17；s 去 12/25 → 18；f 去 10/22 → 18。
四维合计 73.00；无附加最终分 73.00；再 +9 附加 → 82.00（可大于 100 只受单笔 ≤10 约束）。

### 3.4 排名排序

`最终分降序 → 同分比较四维平均（责任心 → 时间管理能力 → 学生工作能力 → 部门契合度，
逐维两位小数降序比较）→ 仍同分按学号升序`；名次连续、无并列。
例：A、B 同 72.00，A 责任心平均 24 > B 20 → A 在前。

## 4. 名单解析规则

### 4.1 统一解析管线（文本与 Excel 共用）

- 学号：恰好 10 位独立数字串 `(?<![0-9])[0-9]{10}(?![0-9])`。
- 姓名链：`[汉字]{1,}([·・•．][汉字]{1,}){0,3}`，整名 ≥2 字、≤64 字；支持少数民族
  `麦麦提·吐尔逊` 写法；空格分隔的两段名只取第一段（请用 · 连写）。
- 行配对：优先「姓名…学号」——取**第一个其后存在学号**的汉字链为姓名，学号取其后第一组
  10 位数字；整行无此顺序退化「学号…姓名」；姓名与学号间隔 ≤80 字符。
- 统计口径：首个可解析行之前的非空行视为题头区（不计跳过）；其后坏行计跳过并给 ≤3 样例；
  空行忽略；幂等按学号（重复=更新姓名不新增）。

### 4.2 Excel（.xlsx/.xls）行提取（二期，POI 5.2.5）

- 识别：文件头魔数（ZIP `PK..` → xlsx；OLE `D0 CF 11 E0` → xls），辅以扩展名。
- 读取：逐 sheet → 逐行 → 单元格文本 → **以 Tab 拼接为一行** → 交给 4.1 同一解析管线；
  **Excel 路径禁止另写一套解析**，表头跳过/坏行/幂等口径与文本完全一致。
- 单元格规则：数字单元格 `BigDecimal.valueOf(numeric).stripTrailingZeros().toPlainString()`，
  **禁止科学计数法**（2.02312E9 → 2023120000）、纯整数不带小数尾；日期格式数字按显示格式取
  文本；公式取缓存结果（同上）；空单元格/合并区非左上角/错误格 → 空串；全空行跳过。
- 导入报告编码标签：`Excel(.xlsx)` / `Excel(.xls)`。

### 4.3 验收样例统计（txt/xlsx/xls 口径一致）

| 文件 | 成功解析 | 新增 | 更新 | 跳过 |
|---|---|---|---|---|
| samples/名单样例-规整.txt | 8 行 | 8 | 0 | 0 |
| samples/名单样例-乱序.txt | 10 行 | 9 | 1 | 3（11 位手机号行 / 18 位连写数字行 / 无学号行） |
| samples/名单样例-四维.xlsx（scripts/gen-excel-samples.py 生成） | 同上 | 9 | 1 | 3 |
| samples/名单样例-四维.xls（同上） | 同上 | 9 | 1 | 3 |

## 5. core 层公开 API 清单（★ GUI/CLI 复用接口）

### 5.1 服务类与 DTO

| 类 | 性质 |
|---|---|
| `scoring.core.ScoringService` | ★ 门面（public final；单进程单实例使用） |
| `scoring.core.dto.*` | ★ 值对象（不可变 record/enum） |
| RosterParser / ExcelRosterReader / Store | 包内私有实现，非公开 API（勿依赖） |

### 5.2 ScoringService 方法清单

> 通用约定：非法参数/状态冲突抛 `IllegalArgumentException`/`IllegalStateException`（中文消息可直接展示）。
> 四维参数各 0~25、两位小数；附加分单笔 0~10、两位小数、原因必填。

| 方法 | 用途 |
|---|---|
| `ScoringService(String jdbcUrl)` / `void close()` | 打开（自动建表/迁移）/关闭 |
| `String migrationNotice()` | 本次打开发生旧库迁移的中文提示；无返回 null |
| `ImportReport importRoster(Path) throws IOException` | 导入 txt/csv/xlsx/xls（魔数识别，统一管线） |
| `List<CandidateInfo> listCandidates()` | 全部候选人（学号升序） |
| `List<CandidateInfo> searchCandidates(String)` | 纯数字→学号精确或前缀（超 10 位取前 10 位）；其它→姓名包含；≤20 |
| `CandidateInfo getCandidate(String)` / `currentInterviewing()` | 取单个 / 当前面试中（无=null） |
| `CandidateDetail candidateDetail(String)` | 完整明细（四维平均/合计/最终分动态计算） |
| `CandidateInfo addCandidate(String name, String no)` | 手动新增（学号恰 10 位且唯一、姓名汉字链校验） |
| `CandidateInfo updateCandidateName(String no, String name)` | 改名（任意状态） |
| `CandidateInfo updateCandidateStudentNo(String old, String new)` | 改学号（级联迁移 score/bonus/op_log；面试中禁止；新号冲突拒绝） |
| `void deleteCandidate(String no)` | 删除（级联删除评分/附加/日志；面试中禁止；调用方二次确认） |
| `CandidateInfo beginInterview(String no)` | 开始/恢复面试（全局唯一；FINISHED 拒绝） |
| `ScoreItem addInterviewScore(no, r, t, s, f)` | 面试中录入一条四维评分（即时入库+记日志） |
| `ScoreItem deleteLastInterviewScore(no)` | 删除最近一条（误输入；可撤销） |
| `FinishResult finishInterview(no, boolean confirmBelowThree)` | 结束评分（n≥3 直接完成；n=1~2 预览→二次确认；n=0 拒绝） |
| `ScoreItem addMakeupScore(no, r, t, s, f)` | 补录一条完整四维评分（仅 FINISHED，自动重算） |
| `BonusItem addBonus(no, BigDecimal amount, String reason)` | 附加分（单笔 ≤10、原因必填、任意状态） |
| `OpLogEntry latestOperation()` / `UndoResult undoLatest()` | 撤销预览 / LIFO 撤销并重算（边界见 §8.4） |
| `List<RankRow> ranking()` | 排名（排序见 §3.4） |
| `int exportCsv(Path, boolean includeUnfinished) throws IOException` | 导出（列见 §5.4；UTF-8 BOM） |
| `SystemStats stats()` | 状态统计 |
| `void resetAll()` | 初始化：清评分/附加/日志、候选人回 PENDING（名单保留） |
| `List<String> resetTargetPreview()` | 彻底重置将删除的文件预览（确认对话框用） |
| `List<String> resetEverything()` | 彻底重置：关库→删文件（库+伴生+数据目录 CSV）→重建空库，返回已删列表 |

| DTO | 关键字段 |
|---|---|

### 5.4 CSV 导出列（二期，按此顺序）

`排名(未完成留空),学号,姓名,责任心,时间管理能力,学生工作能力,部门契合度,四维合计,平均方式,
评分记录数,附加分明细(多笔合并，每笔 `分值(理由)`，用 `;` 连接),附加分合计,最终分`
（UTF-8 BOM；单元格转义+防公式注入；未完成行名次与分数留空，记录数与附加明细保留供备份）。

### 5.5 GUI/CLI 典型调用序列（四维版）

```
启动:  new ScoringService(url) → migrationNotice()? 提示 → currentInterviewing()? 弹「恢复面试」
导入:  importRoster(Path) → 展示 ImportReport
面试:  searchCandidates → beginInterview → 循环 addInterviewScore(no,r,t,s,f)
       → 「结束评分」finishInterview(no,false)；!completed && belowThree → 二次确认框 → finishInterview(no,true)
补录:  addMakeupScore(no,r,t,s,f)（仅 FINISHED，否则提示原因）
附加:  addBonus(no, amount≤10, reason 必填)
撤销:  latestOperation() 预览 → 确认 → undoLatest() → 刷新明细/排名
名单管理: addCandidate / updateCandidateName / updateCandidateStudentNo / deleteCandidate（各自确认）
排名/导出: ranking() + exportCsv(file, includeUnfinished)
初始化: 风险提示 →（可先备份）→ 第二次确认（YES）→ resetAll()
彻底重置: resetTargetPreview() 展示删除文件清单 → 双重确认（第二次输入「彻底重置」）
         → resetEverything() → 刷新全部视图回全新状态
退出:  close()
```

写操作完成后必须刷新相关明细/排名视图（最终分为动态计算值）。

## 6. CLI 命令与菜单流程

### 6.1 命令

```
bash scripts/fetch-libs.sh [-x http://127.0.0.1:7890]   # 下载 H2 + POI（代理可选、不写死）

bash scripts/gen-excel-samples.py                        # 生成 samples/名单样例-四维.xlsx/.xls（python3）
bash scripts/self-test.sh                                # 二期端到端自测（断言全流程）
bash scripts/acceptance.sh                               # 一键：依赖→编译→自测→汇总
bash scripts/run.sh                                      # 中文交互菜单；run.sh import [名单路径] 非交互导入
```
Windows：`scripts\fetch-libs.bat [-x 代理]`、`build.bat`、`run.bat`（先 `chcp 65001`、需 JDK 17）。

### 6.2 主菜单（二期）

| 编号 | 功能 | 说明 |
|---|---|---|
| 1 | 导入名单文件 | txt/csv/xlsx/xls；回车=默认 名单.txt；打印 成功/新增/更新/跳过+样例/编码 |
| 2 | 面试打分（四维） | 搜索→确认→循环：1 添加评分（依次输入 责任心/时间管理/学生工作/部门契合，各 0~25）/ 2 删除上一条 / 3 结束评分（n≥3 自动逐维去极值；n=1~2 提示二次确认；n=0 拒绝）/ 0 暂存续面 |
| 3 | 查看候选人名单与状态 | 关键字过滤（回车=全部） |
| 4 | 查看排名与评分明细 | 四维列排名表 + 排序说明；输学号看逐条明细 |
| 5 | 导出 CSV | 范围 1 仅已完成 / 2 全部（含未完成，适合备份）；默认 data/导出_时间戳.csv |
| 6 | 分数补录 | 仅 FINISHED，补一条**完整四维记录**，自动重算 |
| 7 | 分数附加 | 单笔 0~10、必填原因、可多笔（提示基础 100+附加、无总上限） |
| 8 | 撤销 | 预览最近操作→确认→重算（可连续撤销） |
| 9 | 初始化系统 | 清评分/附加/日志、名单回 PENDING（保留名单）；二次确认第二重输入 `YES` |
| 10 | 名单管理 | 子菜单：1 新增 / 2 改名 / 3 改学号（级联，展示迁移提示）/ 4 删除（级联+确认）/ 5 查看 / 0 返回 |
| 11 | 彻底重置 | **危险**：删除一切数据与库文件（§8.6）；先列删除清单，第一重确认 y/n，第二重输入 `彻底重置` |
| 0 | 退出 | |

非交互：`Main import [文件]` 导入一次即退出（失败退出码 1）。

## 8. 歧义语义说明与已知限制

### 8.1 补录
仅 FINISHED；补录 = 追加一条**完整四维记录**（四值必填、各 0~25），自动重算（重新逐维去极值）。

### 8.2 附加分
单笔 0~10、两位小数、原因必填 ≤200 字、可多笔；合计直接并入最终分，**无 100 总上限**
（“基础四维 ≤100 + 附加”写入文档与导出）。旧库迁移保留历史附加分（历史单笔可能 >10，
仅约束新录入）。

### 8.3 评分不足 3 条
n=1~2 结束面试需二次确认（按普通平均）；n=0 拒绝结束；n 以“记录条数”计（每条含四维）。
撤销/补录导致条数变化时按新口径整体重算（≥3 自动回去极值）。

### 8.4 撤销
对象：ADD_SCORE（录入/补录）、DEL_SCORE（面试中删除上一条）、ADD_BONUS（附加分）。
LIFO、持久化、支持深度=日志条数（到日志起点）；每次撤销重算该候选人最终分。边界：
不可跨初始化；已结束者不可撤到 0 条记录（拒绝并提示，可用补录/附加或初始化解决）；
撤销不改面试状态；被删评分按日志快照恢复原 id/原四维/原录入时间。

### 8.5 名单 CRUD 级联
改学号/删除自动级联 score/bonus/op_log；面试中（INTERVIEWING）禁止改号与删除
（先结束面试或初始化）；删除不可逆（CLI 二次确认；GUI 同级确认）；被删学号可重新添加。

### 8.6 初始化 vs 彻底重置（务必区隔）

| | 初始化（菜单 9 / resetAll） | 彻底重置（菜单 11 / resetEverything） |
|---|---|---|
| 候选人名单 | 保留 | **删除** |
| 评分/附加/日志 | 清空 | 随库文件删除 |
| 数据库文件 | 保留 | **删除并原地重建**（*.mv.db/.trace.db/.lock.db） |
| data/ 下导出/备份 CSV | 保留 | 一并删除 |
| 确认 | 二次确认（第二重输 `YES`） | 双重确认（第二重输 **`彻底重置`** 全词，防混淆） |
| 迁移归档表 | 保留 | 随库文件删除 |

`resetEverything()`：关连接 → 按 JDBC URL 定位文件 → 删除目标 → 重连建表 → 返回已删除
文件列表；仅支持 `jdbc:h2:file:` 文件库；调用后同一服务实例立即可用（空库）。

### 8.7 旧库迁移（score.points → 四维）
自动检测（score 表含 points 列且无 r 列）→ `score/op_log` 改名归档
`score_legacy_v1 / op_log_legacy_v1`（日志引用旧行，一并归档以免撤销链报不一致）→ 建新表。
候选人名单保留，但其旧“已结束/面试中”状态一并**重置为未面试**（旧状态无四维评分支撑，
避免排名对“0 条记录的已结束者”误算）；**旧评分不换算进四维**（取舍写明；留档请先导出一期 CSV）。
`migrationNotice()` 提供提示文本；归档表不再读写，仅彻底重置随库删除。
旧库 bonus 的 DB CHECK 仍为 0~100（历史宽容），新录入由服务端统一限 0~10。

### 8.8 已知限制
1. 一行一条记录；Excel 合并单元格按空串；多 sheet 顺序拼接（题头区统计以首个可解析行为界）。
2. 姓名须为汉字链（含 ·・•． 连接段）；空格分隔的两段名只取首段（请用 · 连写）；ASCII `.` 不作姓名内部点。
3. 一行内 10 位连续数字可能与汉字误配（概率低，名单请保证学号列独立）；姓名与学号间隔 >80 字符不配对。
4. 分值约束：维度 0~25、附加单笔 0~10、均两位小数；超出拒绝（无静默舍入）。
5. 单进程单实例：H2 文件库独占，CLI/GUI 不得同时打开同一库文件；服务非线程安全。
6. 路径相对启动目录（脚本 cd 项目根）；Windows 控制台需 `chcp 65001`。
7. 撤销不跨初始化；初始化/彻底重置/删除均不可撤销。
8. 平均按两位小数逐维舍入后再求和（保证界面/导出“四维列之和 = 四维合计”恒等）。
