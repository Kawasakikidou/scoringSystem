# 学生组织面试评分系统 —— 接口文档

> 适用版本：Java 17 LTS 后端 + CLI + GUI（core 分层，CLI/GUI 两个壳复用同一 core）
> 配套文档：`docs/CLI使用说明.md`、`docs/GUI使用说明.md`（面向非技术面试官的操作手册）、`docs/自测记录.md`（验收自测）
> 本项目的全部接口与规则以本文档为准；CLI 与 GUI 都只是 core 的交互壳，业务规则只在 core 实现一次（见第 5 节）。

## 2. 数据模型与表结构

### 2.1 候选人（candidate）—— 名单与面试状态

| 列 | 类型 | 说明 |
|---|---|---|
| student_no | VARCHAR(10) PK | 学号：恰好 10 位数字，名单去重键 |
| name | VARCHAR(64) | 姓名；重复导入同号时以最后一次为准更新 |
| status | VARCHAR(16) | PENDING=未面试 / INTERVIEWING=面试中 / FINISHED=已结束面试 |
| finished_at | TIMESTAMP | 面试完成时间（结束评分时写入），未完成时为 NULL |
| imported_at / updated_at | TIMESTAMP | 首次导入 / 最近更新时间（自动维护） |

状态机（由 ScoringService 强制，见 5.5）：
`PENDING --开始面试--> INTERVIEWING --结束评分(≥1条)--> FINISHED`；`INTERVIEWING` 可跨进程暂存续面；`FINISHED` 不可重开（补录/附加除外）；`resetAll()` 将全部候选人重置为 `PENDING`（名单保留）。

### 2.2 普通评分（score）—— 面试打分与补录共用

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGINT 自增 PK | 撤销/删除的引用锚点 |
| student_no | VARCHAR(10)（逻辑外键→candidate） | 所属候选人 |
| points | DECIMAL(6,2) | 分值，CHECK 0~100，最多两位小数 |
| created_at | TIMESTAMP | 录入时间（撤销删除评分时原样恢复） |

### 2.3 附加分（bonus）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGINT 自增 PK | 撤销的引用锚点 |
| student_no | VARCHAR(10)（逻辑外键→candidate） | 所属候选人 |
| amount | DECIMAL(6,2) | 附加分值，CHECK 0~100，最多两位小数 |
| reason | VARCHAR(200) | 加分原因（必填，去空白后非空） |
| created_at | TIMESTAMP | 记录时间 |

### 2.4 操作日志（op_log）—— 撤销功能的数据源

| 列 | 类型 | 说明 |
|---|---|---|
| seq | BIGINT 自增 PK | 全局递增，撤销按 LIFO 弹此列 |
| student_no | VARCHAR(10) | 被操作候选人 |
| op_type | VARCHAR(12) | `ADD_SCORE`（面试打分/补录入库）、`DEL_SCORE`（面试中删除上一条）、`ADD_BONUS`（附加分） |
| ref_id | BIGINT | 被操作行的 id（score.id / bonus.id） |
| points / reason | DECIMAL(6,2) / VARCHAR(200) | 分值 / 原因快照（撤销 DEL_SCORE 时用快照原值恢复） |
| occurred_at | TIMESTAMP | 被操作行自身的录入时间快照（DEL_SCORE 还原用） |
| created_at | TIMESTAMP | 日志时间 |

日志随数据库持久化，**支持深度 = 日志条数（到日志起点为止）**；`resetAll()` 清空日志，因此**撤销不能跨越初始化边界**（详见第 8 节）。

### 2.5 存储位置与配置

- H2 嵌入式文件库：`data/scoring.mv.db`（单文件、本地存储、无网络/服务进程）。
- JDBC URL 解析顺序：`-Dscoring.db.url=…` → 环境变量 `SCORING_DB_URL` → 默认 `jdbc:h2:file:data/scoring`（相对**启动目录**）。GUI 接入时应自行创建 URL 中目录的父目录后构造 `ScoringService`。
- 选型理由：H2 纯 Java 单 jar，无任何原生 .dll/.so，Java 17 直接可跑，跨平台打包（第 7 节两种 exe 形态）无原生依赖坑；单文件、JDBC 标准接口、事务与崩溃一致性有保障。对比 SQLite-JDBC：其驱动内嵌按平台拆包加载的原生库，Linux/Windows/macOS 分发与杀软误报风险更高，故不采用。更轻的纯文本方案不具备事务与一致性，不满足「数据库」要求。

## 3. 最终分计算规则

### 3.1 公式

```
最终分 = 平均分 + Σ附加分          （两者均保留两位小数，HALF_UP 舍入）

平均分 =
  n ≥ 3：去极值平均 = (排序后去掉 1 个最高、1 个最低) 剩余 n-2 条之和 / (n-2)
  n = 1～2：普通平均 = 各条之和 / n   （需用户在结束面试时二次确认）
  n = 0：不允许结束面试（提示先录入至少 1 条）
```

- 并列最高/最低只各去掉**一条**（如 `80,80,90,90` → 去一个 80、一个 90，平均 `(80+90)/2=85.00`）。
- 附加分**不参与**去极值/普通平均，只求和后并入最终分；多笔附加分分别记录并单独列示。
- **最终分不落库**：每次由 `candidateDetail()/ranking()/exportCsv()` 从明细动态计算，杜绝「改了分忘了重算」的不一致。
- 补录后自动重算 = 重新执行上表公式（评分 ≥3 条则重新去极值；补录后仍不足 3 条时按普通平均口径）。
- 撤销/删除评分后同样重算。
- 若最终分相同：按学号升序稳定排序（因此名次唯一、无并列）。

### 3.2 例子

| 场景 | 普通评分 | 附加分 | 平均分 | 最终分 |
|---|---|---|---|---|
| 3 条去极值 | 80, 90, 85 | +5（才艺） | (80+85+90 去 80、90)=85.00 | 90.00 |
| 4 条含并列 | 80,80,90,90 | 无 | (80+90)/2=85.00 | 85.00 |
| 2 条（二次确认） | 70, 90 | +2 | (70+90)/2=80.00 | 82.00 |
| 1 条（二次确认） | 88 | 无 | 88.00 | 88.00 |
| 0 条 | — | — | 拒绝结束面试 | — |

## 4. 名单解析规则（歧义策略）

### 4.1 学号

- 恰好 **10 位数字** 的独立数字串：正则 `(?<![0-9])[0-9]{10}(?![0-9])`。
- 11 位手机号、12+ 位长串、夹在长数字串中间的 10 位数字都**不会**被误判为学号。

### 4.2 姓名

- 姓名 token = 连续汉字段，支持少数民族姓名「多段汉字 + 中间点」：
  `[\u3400-\u9FFF]{1,}([·・•．][\u3400-\u9FFF]{1,}){0,3}`，整名 ≥2 字、段间无空白。
  支持的中间点：`·`(U+00B7)、`・`(U+30FB)、`•`(U+2022)、`．`(U+FF0E)。
  例：`麦麦提·吐尔逊`、`阿依古丽·买买提`、`艾力·玉素甫` 均整段提取。
- 汉字范围 `\u3400-\u9FFF` 覆盖扩展 A 生僻字。

### 4.3 一行内的配对与顺序

- 每行只取**第一组**「姓名+学号」；顺序解析规则（确定性）：
  1. 第一优先「姓名在前、学号在后」：按从左到右扫描汉字链，取**第一段其后存在学号的汉字链**为姓名，学号取该链之后的第一组 10 位数字（兼容 `姓名,学号`、`姓名 部门 学号` 等乱序多列——部门等后续汉字列不会抢先）；
  2. 若整行没有「姓名…学号」顺序（如 `学号,姓名` 竖列），退化为「学号在前、姓名在后」：取第一组学号及其后第一段汉字链。
- 姓名与学号之间允许 ≤80 个任意字符（容纳其它列）；分隔符不限（逗号/Tab/空格/顿号/无分隔）。
- 无法解析（如无学号、学号位数不符）的行按 4.4 计入跳过。

### 4.4 统计口径（导入报告：成功 X 行、跳过 Y 行）

- **成功 X 行** = 解析出记录的**行数**（同一文件内重复学号也算解析成功，第 2 行起按「更新」计数，不新增记录）。
- **跳过 Y 行** = 首个可解析行**之后**无法解析的非空行（如只有手机号的行、学号位数不对的行、无学号的行）。最多展示 3 条样例行供排查。
- 文件开头的**题头/表头区**（首个可解析行之前的非空行，如“招新名单”“姓名,学号,备注”）不计入跳过；**空行**不计入。
- 编码自动探测：UTF-8 BOM → UTF-8 → GB18030 → ISO-8859-1（单字节兜底），报告会显示实际编码。
- 按学号幂等：已存在学号 → 更新姓名为本次值（面试状态、已有评分不动）；不存在 → 新增。

### 4.5 两个验收样例的预期统计（导入到空库）

| 文件 | 成功解析 | 新增 | 更新 | 跳过 | 说明 |
|---|---|---|---|---|---|
| `samples/名单样例-规整.txt` | 8 行 | 8 | 0 | 0 | 统一「姓名,学号」竖列，含 3 个 `·` 点号姓名 |
| `samples/名单样例-乱序.txt` | 10 行 | 9 | 1 | 3 | 乱序多列、学号在前后都有、含点号姓名；跳过的 3 行 = 11 位手机号行 / 18 位连写数字行 / 无学号行；1 次同号重复幂等更新 |

## 5. core 层公开 API 清单（★ GUI 直接复用的接口）

### 5.1 包与类

| 类 | 性质 | 说明 |
|---|---|---|
| `scoring.core.ScoringService` | ★ 服务类（public，唯一门面） | 全部业务操作；GUI 持有**单例**（每窗口一个） |
| `scoring.core.dto.*` | ★ 值对象（public record/enum） | 入参出参全部不可变数据 |
| `scoring.core.RosterParser` / `Store` | 包内私有实现 | 解析器与 H2 DAO，**不属于公开 API**（类名可随时变化） |

### 5.2 ScoringService 方法清单

> 通用约定：`studentNo` 必须为恰好 10 位数字，否则抛 `IllegalArgumentException`（中文消息）；
> 状态/业务冲突抛 `IllegalStateException`（中文消息）；两者都未捕获=调用错误，GUI 可直接把 `getMessage()` 展示给用户。

| 方法签名 | 用途（GUI 用法提示） |
|---|---|
| `ScoringService(String jdbcUrl)` | 构造并打开 H2 文件库（自动建表）。GUI：文件选择器选目录→拼 `jdbc:h2:file:<目录>/scoring`→先 `mkdirs` 再构造 |
| `void close()` | 关闭数据库连接。GUI：窗口关闭时调用 |
| `ImportReport importRoster(Path file) throws IOException` | 导入名单（解析+幂等去重）。GUI：文件选择器选 txt/csv 后调用，用报告弹提示 |
| `List<CandidateInfo> listCandidates()` | 全部候选人（学号升序）。GUI：名单/状态表格 |
| `List<CandidateInfo> searchCandidates(String keyword)` | 搜索：纯数字→学号精确匹配，其次前缀匹配（输入超过 10 位时取前 10 位参与匹配）；其它→姓名包含匹配；≤20 条。GUI：搜索框 |
| `CandidateInfo getCandidate(String studentNo)` | 单个候选人。不存在抛 IllegalArgumentException |
| `CandidateInfo currentInterviewing()` | 当前“面试中”候选人；无返回 null。GUI：启动时据此弹出「恢复上次未完成面试」 |
| `CandidateDetail candidateDetail(String studentNo)` | 完整明细：普通评分列表、附加分列表、平均分、平均方式、附加合计、最终分（未结束为 null）。GUI：明细页唯一数据源 |
| `CandidateInfo beginInterview(String studentNo)` | 开始/恢复面试；FINISHED 拒绝；别人 INTERVIEWING 时拒绝。GUI：“开始面试”按钮 |
| `ScoreItem addInterviewScore(String studentNo, BigDecimal value)` | 面试中录入一条评分（即时入库+记日志）。GUI：分数输入框“保存” |
| `ScoreItem deleteLastInterviewScore(String studentNo)` | 面试中删除最近一条（误输入；本身可被撤销）。GUI：“删除上一条” |
| `FinishResult finishInterview(String studentNo, boolean confirmBelowThree)` | 结束评分。≥3 条→直接完成；1~2 条→返回 `completed=false` 的预览，GUI 弹二次确认框后以 `confirm=true` 再调一次；0 条抛异常。GUI 流程见 5.5 |
| `ScoreItem addMakeupScore(String studentNo, BigDecimal value)` | 补录（仅 FINISHED），自动重算。GUI：补录表单 |
| `BonusItem addBonus(String studentNo, BigDecimal amount, String reason)` | 附加分（任意状态，原因必填），自动重算（若已结束）。GUI：附加表单 |
| `OpLogEntry latestOperation()` | 最近一条可撤销操作；无返回 null。GUI：“撤销”按钮的预览文本 |
| `UndoResult undoLatest()` | LIFO 撤销最近一条并重算；无日志抛 IllegalStateException。GUI：撤销成功提示 |
| `List<RankRow> ranking()` | 排名（仅 FINISHED，最终分降序→学号升序）。GUI：排名表 |
| `int exportCsv(Path file, boolean includeUnfinished)` | 导出 CSV（UTF-8 **带 BOM**，Excel 直开不乱码；单元格转义+防公式注入）。`includeUnfinished=true` 时未结束者排在末尾（名次与分数留空、明细保留）。GUI：“导出”另存对话框 |
| `SystemStats stats()` | 总数/状态分布/评分与附加分条数。GUI：仪表盘/初始化前提示 |
| `void resetAll()` | 初始化：清空评分、附加分、日志，候选人回 PENDING（名单保留）。**GUI 必须自行先弹两次确认**（第 8 节） |
| 常量 `MIN_VALUE/MAX_VALUE` | 分值域 0～100，两位小数（评分与附加一致） |

### 5.4 GUI 典型调用序列（推荐流程）

```
启动:   new ScoringService(url) → currentInterviewing()（非 null 则提示恢复）
导入:   选择文件 → importRoster(Path) → 展示 ImportReport
面试:   searchCandidates(关键字) → 列表确认 → beginInterview(no)
        → 分数输入 → addInterviewScore(no, v)（循环）
        → 「结束评分」→ finishInterview(no,false)
             若 !completed（belowThree）→ 弹二次确认 → finishInterview(no,true)
        → 展示 FinishResult
补录:   searchCandidates → 校验 status==FINISHED → addMakeupScore → 刷新明细
附加:   searchCandidates → addBonus(no, amount, reason) → 刷新明细
撤销:   latestOperation()（预览）→ 确认 → undoLatest() → 刷新明细/排名
排名:   ranking()（已完成）＋ listCandidates()（未完成区）
导出:   exportCsv(File, includeUnfinished)
初始化: stats() 展示风险 → 两次确认（第二次要求输入 YES/明确点击）→ resetAll()
退出:   close()
```

### 5.5 面试状态机细节（GUI 复刻时务必一致）

- 全局**同时最多一名** INTERVIEWING；`beginInterview` 对已 FINISHED 者抛错。
- `addInterviewScore` 仅 INTERVIEWING 可用；FINISHED 请走 `addMakeupScore`；PENDING 请先 `beginInterview`。
- `deleteLastInterviewScore` 仅 INTERVIEWING 可用。
- 结束面试要求至少 1 条普通评分（0 条时抛错）；1~2 条必须经 `FinishResult` 二次确认，3 条及以上直接完成。
- 面试中途退出/崩溃：状态停留在 INTERVIEWING，评分保留；重启后 `currentInterviewing()` 恢复续面。

## 6. CLI 命令与菜单流程

### 6.1 启动命令

```
bash scripts/acceptance.sh    # 一键验收：环境检查+依赖下载+编译+端到端自测（推荐）
bash scripts/fetch-libs.sh    # 首次：下载 H2 到 lib/
bash scripts/build.sh         # 全量编译（core 独立编译自证 + core+cli）
bash scripts/run.sh           # 进入交互菜单（中文）
bash scripts/run.sh import [名单路径]   # 非交互导入一次后退出（验收/脚本用，默认名单.txt）
```

Windows：`scripts\fetch-libs.bat` → `scripts\build.bat` → 控制台先 `chcp 65001` → `scripts\run.bat`。

### 6.2 主菜单与子流程

| 编号 | 功能 | 流程 |
|---|---|---|
| 1 | 导入名单文件 | 输入路径（回车=当前目录 `名单.txt`）→ 打印“成功 X 行（新增 N、更新 M）/ 跳过 Y 行 + ≤3 条样例” |
| 2 | 面试打分 | 若存在未完成面试→询问是否继续；否则输入姓名/学号关键字→列出匹配结果→确认序号→进入面试循环：`1 添加评分 / 2 删除上一条 / 3 结束评分 / 0 暂存退出`；每条评分保存后提示可继续添加；结束评分时 ≥3 条直接结算，1~2 条先提示再二次确认（y/n）；0 条则拒绝结束 |
| 3 | 查看名单与状态 | 可选关键字过滤；显示 学号/姓名/状态/完成时间 及统计 |
| 4 | 查看排名与明细 | 显示排名表（含平均方式、附加合计、条数）与未完成人数；可输学号查看某人评分明细（回车 / q / 0 返回） |
| 5 | 导出 CSV | 选范围（1 仅已完成 / 2 全部，回车默认 1）→ 路径（回车默认 `data/导出_时间戳.csv`）→ 打印行数与 BOM 提示 |
| 6 | 分数补录 | 搜索→确认候选人（非 FINISHED 会说明原因并返回）→ 输入分数→ 打印最新平均/最终分；可连续为多人补录 |
| 7 | 分数附加 | 搜索→输入分值→输入必填原因→打印附加合计与最新最终分（未结束则提示计入时机） |
| 8 | 撤销操作 | 打印最近一条可撤销操作→确认（默认否）→撤销并打印结果（剩余条数/最新最终分）；可连续撤销 |
| 9 | 初始化系统 | 风险清单→询问是否先导出备份（y/n/q）→二次确认需输入 `YES` → 清空评分与状态、保留名单 |
| 0 | 退出 | 关闭数据库连接（数据持久化在 `data/scoring.mv.db`） |

所有输入均可输入 `q` 取消（编号选择除外）；非法输入会提示后重试；业务错误以“操作未完成：原因”形式提示，不打断会话。

## 7. 打包指引（仅方案，不执行）

### 7.1 两种形态的本质区别（务必先读）

| | CLI 版（控制台程序） | GUI 版（无黑框） |
|---|---|---|
| 有无控制台窗口 | **必须有**：中文交互菜单靠控制台 stdin/stdout 工作 | **必须没有**：界面自绘，控制台窗口多余 |
| 交互通道 | 键盘输入 + 文本输出 | 鼠标/键盘 + 界面组件 |
| 打包要点 | 启动器保持 console 子系统 | 启动器切换为 GUI 子系统（`javaw` / `headerType=gui`；jpackage 缺省即 GUI） |
| 结论 | **“无黑框”形态只适用于 GUI 版**。纯 CLI 版若做成无控制台窗口，将没有任何输入输出的承载通道，程序形同不可用 | 本文 5 节的 core API 即 GUI 的调用面 |

### 7.2 通用前置（两种形态相同）

1. 已安装 JDK 17（打包机与运行机位数一致）。
2. 产出可运行 jar（把编译产物与依赖装进一个目录）：
   ```
   # 方案 A（推荐，简单直接）：全部 jar 平铺，用 jpackage 的 --input
   jar --create --file scoring-cli.jar --main-class scoring.cli.Main -C out .
   # 目录结构：<app>/scoring-cli.jar + <app>/h2-2.2.224.jar（从 lib/ 复制）
   ```
3. 运行机需要 JDK/JRE 17；或使用 `jlink` 裁剪后随包分发（不在本任务范围，仅提示）。

### 7.3 CLI 版打包成控制台 exe（两种任选）

**方案 A：jpackage（官方工具）**
```
jpackage --type exe --name ScoringCLI \
  --input <app目录> --main-jar scoring-cli.jar --main-class scoring.cli.Main \
  --java-options "-Dfile.encoding=UTF-8" \
  --win-console    # 显式声明控制台子系统（默认对非 GUI 主类即控制台，写明更稳）
```
生成 `<ScoringCLI>/ScoringCLI.exe`。要点：
- 双击 exe 会弹出控制台窗口——这是 CLI 版的**必要行为**，不是缺陷；
- 运行时把工作目录设为含 `data/` 与 `名单.txt` 的文件夹（快捷方式“起始位置”），数据库与默认名单文件都在其中；
- 中文显示：控制台执行 `chcp 65001`，或使用 Windows Terminal；
- 若提示缺少 Java，运行机先装 JRE 17 或改用 `--runtime-image`（`jlink` 产物）。

**方案 B：launch4j（XML 配置）**
```xml
<launch4jConfig>
  <headerType>console</headerType>      <!-- 关键：控制台形态 -->
  <jar>scoring-cli.jar</jar>
  <outfile>ScoringCLI.exe</outfile>
  <jre><minVersion>17</minVersion></jre>
  <classPath><mainClass>scoring.cli.Main</mainClass></classPath>
  <singleInstance>true</singleInstance>
</launch4jConfig>
```
用 launch4j GUI/命令行按上述配置生成 ScoringCLI.exe，`h2-2.2.224.jar` 需与 jar 同目录或放入 `<classPath>` 声明的路径。

### 7.4 GUI 版打包成无黑框 exe

> GUI 已随本仓库交付：`src/gui/java/scoring/gui/Main.java`（JavaFX 17，**只依赖 core**，第 5 节 API）。
> **一键脚本已提供**：Windows 打包机上双击 `scripts\package-win.bat` 即可产出
> `dist\ScoringGUI-1.0.0.exe`（自动补依赖→编译→jar→jpackage，无需手工复制命令）；
> 以下命令示例供理解/自定义（Windows 打包机上执行）。完整步骤见 `docs/GUI打包指南-win.md`。
> 前置：JDK 17（完整版，含 `jpackage`）；`scripts/fetch-gui-libs.bat` 一次自动就位
> `lib/openjfx-17/windows/`（SDK，编译/开发用）与 `lib/openjfx-17/windows-jmods/`（jmods，打包用）。

**第 1 步：产出 GUI 可运行 jar（classes + CSS 资源已在 `out/` 中）**

```
jar --create --file scoring-gui.jar --main-class scoring.gui.Main -C out .
```

**第 2 步：准备输入目录**（jpackage 的 --input 会把其中全部 jar 放到应用 classpath）

```
mkdir app-input
copy scoring-gui.jar app-input\
copy lib\h2-2.2.224.jar app-input\
```

**第 3 步（方案 A）：jpackage 打包（GUI 子系统缺省即无黑框，与 package-win.bat 实际参数一致）**

```
jpackage --type exe --name ScoringGUI --app-version 1.0.0 --vendor "ScoringGUI" ^
  --input app-input --main-jar scoring-gui.jar --main-class scoring.gui.Main ^
  --module-path lib\openjfx-17\windows-jmods ^
  --add-modules javafx.controls,javafx.fxml,java.sql,java.logging,java.management,java.naming ^
  --java-options "-Dfile.encoding=UTF-8" ^
  --dest dist --win-shortcut --win-per-user-install
```

要点：

- **module-path 必须用 `windows-jmods/`（jmods 包），不能用 SDK 的 `windows/lib`（松散 .dll 不会被
  jlink 链入运行时，产出的安装包启动时会报 "no suitable pipeline found"）**。`javafx.jmods/` 由
  `fetch-gui-libs.bat` 一并下载（zips 为 Gluon 官方 `_bin-jmods.zip`）；
- **`--add-modules` 必须同时包含 JDK 基础模块**（`java.sql` 等）：classpath 应用没有「主模块」，
  jlink 只按本清单收集模块，缺 `java.sql` 会导致 H2/JDBC 启动即 `NoClassDefFoundError`；
- **不要加 `--win-console=false`**：`--win-console` 是无值开关（加了会变成「控制台应用」并弹黑框），
  jpackage 缺省即 GUI 子系统、无黑框；`--win-console=false` 的写法在新版 jpackage 会报「无效选项」；
- `--win-per-user-install`：按用户安装免管理员权限；需要全机器安装则去掉并在安装时允许为所有人；
- 数据库位置：优先「启动目录/data/」，若不可写（如装进 `C:\Program Files\`）自动退回
  「用户主目录 `.scoring-gui/data/`」（见 GUI 壳层 `Main.defaultDbUrl()`）；无需给 exe 配任何参数。

**方案 B：launch4j `headerType=gui`**

```xml
<headerType>gui</headerType>   <!-- 关键：gui 形态（内部以无控制台方式启动 JVM） -->
```
注意 launch4j 仅包装启动器：JavaFX 模块路径需通过其 JVM 参数配置
（`--module-path ... --add-modules javafx.controls,javafx.fxml`），并把 openjfx 的 `lib/` 随包分发。

通用注意：GUI 入口不依赖 `System.out/System.in`（core 亦不依赖）；业务规则只在 core 实现一次，
打包产物无需包含任何额外业务代码。

## 8. 歧义语义说明与已知限制

### 8.1 补录（menu 6 / addMakeupScore）

- 仅允许 **FINISHED** 候选人（PENDING/INTERVIEWING 会拒绝并说明）。
- 补录一条普通评分，立即按第 3 节公式**整体重算**最终分（重新去极值）。
- 补录动作记入操作日志（ADD_SCORE），可被「撤销」删除并再次重算。
- 面试完成时间（finished_at）不因补录改变；最终分始终是动态值。

### 8.2 附加分（menu 7 / addBonus）

- 任意状态候选人可加（如才艺、比赛、展示加分），**原因必填**（≤200 字）。
- 附加分只求和、不参与去极值平均，单独列示；最终分 = 平均分 + Σ附加分。
- 允许一人多笔；对已结束者立即反映最终分，未结束者到「结束评分」时计入。
- 附加动作记入日志（ADD_BONUS），可撤销（撤销即删除该笔）。

### 8.3 撤销（menu 8 / undoLatest）

- 撤销对象 = 最近一次“修改评分”的操作：录入/补录评分（ADD_SCORE）、面试中删除上一条（DEL_SCORE）、加附加分（ADD_BONUS）。
- **LIFO、持久化、支持深度 = 当前日志条数**（可连续撤销直到日志起点）；日志随库保存，重启仍可撤销。
- 每次撤销后对该候选人自动重算；若已结束面试，提示最新最终分。
- 边界：
  1. 不能撤销到「已结束面试候选人只剩 0 条普通评分」——此时拒绝并提示（可补录/附加修正，或初始化重来），保证最终分始终可计算；
  2. 不能跨过**初始化**（初始化清空日志）；
  3. 撤销不影响面试状态（FINISHED 撤销后仍 FINISHED；普通评分 1~2 条时按普通平均口径重算）；
  4. 被删除评分的还原会恢复原 id 与原录入时间（快照存储）。
- 初始化、导入、结束面试、暂存本身**不是**可撤销操作。

### 8.4 初始化（menu 9 / resetAll）

- 语义：清空全部普通评分、附加分、操作日志；所有候选人回到 PENDING（含 INTERVIEWING），finished_at 置空；**候选人名单保留**。
- CLI 双重确认：①询问是否先导出备份（建议“全部”范围，未完成者已录明细也可留档）→ ②要求输入 `YES` 才执行。
- GUI 必须自行实现同等级别的二次确认与备份提示，然后才调用 `resetAll()`。

### 8.5 评分不足 3 条（面试结束）

- 1~2 条：结束评分时**先提示**“无法去掉最高/最低，将按普通平均”，**二次确认**后完成；拒绝则继续留在面试中。
- 0 条：拒绝结束（必须先录入至少 1 条）。
- 若候选人以 1~2 条结束后又被撤销/删除，重算按 1~2 条普通平均口径（≥3 条自动回到去极值）。

### 8.6 已知限制（文档承诺的边界）

1. **一行一条记录**：合并多行成一行（含两组以上“姓名+学号”）只取第一组；表头题头不计跳过（见 4.4）。
2. 姓名必须为汉字（含 `·/・/•/．` 连接的少数民族姓名）；用**空格**连接的两段名字（如 `阿依古丽 买买提`）只取第一段——名单制作方请统一用 `·` 连写。
3. ASCII `.` 不作为姓名内部点（避免吞掉列分隔符）。
4. 一行内姓名与学号间隔 >80 字符不配对（正常表格不会出现）。
5. 「姓名在前」模式中若行首存在标题类汉字且其后恰好跟着 10 位数字（如 `接待处2023123456…`），可能把该标题段误作姓名（各行独立成表头的情况极少，出现时请把标题与数据分行）。
6. 10 位数字的电话/号码可能与同行汉字误配（概率极低；请名单中确保学号恰好 10 位数字独立成列）。
7. 分值域统一 0~100、最多两位小数；附加分同域。超出范围/超小数位将被拒绝（不做静默舍入）。
8. 单进程单实例：H2 文件库由持有连接者使用，请勿多进程同时打开同一库文件；服务实例非线程安全（GUI 单线程调用）。
9. 路径相对性：默认名单文件与默认数据库路径均相对**启动目录**；脚本已 cd 到项目根目录。
10. 乱码预防：CSV 固定 UTF-8+BOM；名单文本支持 UTF-8/GB18030 自动探测，极端未知编码回退 ISO-8859-1 时可能乱码（导入报告会显示实际编码）。
11. Windows 控制台中文：需 `chcp 65001` 与 UTF-8 终端（本仓库所有 .bat 已注明）。
12. 撤销不能跨初始化（8.3）；初始化不可撤销。
