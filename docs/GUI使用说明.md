# 学生组织面试评分系统 —— GUI 使用说明（非技术版）

> 本手册面向学生组织面试官（无需编程经验），对应 **图形界面（GUI）版**。
> 命令行（CLI）版请另读 `CLI使用说明.md`；开发者请另读 `接口文档.md`。
> 说明：本文所有截图位置以「📷 截图占位」标注，正式交付时可按描述截取对应界面替换。

---

## 1. 安装与启动

### 1.1 环境要求

- **Windows 10/11（64 位）** 或 Linux；已安装 **JDK 17**（在命令行输入 `java -version` 应显示 `17.x`）。
- 本程序由三个脚本完成准备与启动（Windows 用 `.bat`，Linux 用 `.sh`）：

| 步骤 | Windows | Linux | 说明 |
|---|---|---|---|
| ① 下载组件（仅首次，联网） | `scripts\fetch-libs.bat` 和 `scripts\fetch-gui-libs.bat` | `bash scripts/fetch-libs.sh` 和 `bash scripts/fetch-gui-libs.sh` | 分别下载 H2 数据库驱动与 JavaFX 17 界面组件 |
| ② 编译（仅首次或有更新） | `scripts\build-gui.bat` | `bash scripts/build-gui.sh` | 生成可运行程序 |
| ③ 启动 | `scripts\run-gui.bat` | `bash scripts/run-gui.sh` | 打开评分系统窗口 |

> Windows 用户如在黑窗口中看到中文乱码，先执行 `chcp 65001` 再运行脚本（`run-gui.bat` 已自动设置）。

### 1.2 首次启动

- 双击/运行 `run-gui` 脚本后，会出现约 **1100×720** 的主窗口（可拖拽边缘缩放）。
- **数据目录**：程序自动在程序根目录下创建 `data/` 文件夹，数据库文件为 `data/scoring.mv.db`；无需手工选择。
- 若上次有面试中途退出，启动时会弹出「**恢复上次未完成面试**」对话框：点「确定」直接进入该候选人的打分界面，已录入的评分都在。

## 2. 名单导入

左侧导航点「**名单导入**」→ 点「**选择名单文件并导入…**」→ 在文件选择框中选中名单文件。
支持 **Excel（`.xlsx` / `.xls`，程序按文件自动识别）** 与 `.txt` / `.csv` 文本名单。

### 2.1 名单格式要求

- **每行一个人**，行内含：一段 ≥2 个汉字的姓名 + 恰好 10 位数字的学号；
- Excel 名单：单元格内容同样按「姓名 + 学号」解析（数字学号不会变成科学计数法）；
- 乱序、多列（含部门、电话、备注）不影响导入；姓名含少数民族中间点请用 `·` 连写（如 `麦麦提·吐尔逊`），不要用空格分两段；
- 可多次导入：同一学号只会**更新姓名**，不会重复；面试状态与已有评分不受影响。

### 2.2 导入结果弹窗字段解释

导入完成后弹出结果窗口（统计口径与《接口文档》§4.4 完全一致）：

| 字段 | 含义 |
|---|---|
| 成功解析 X 行 | 解析出「姓名+学号」的数据行数（含库内已有学号的更新行） |
| 新增 N 人 | 库里此前没有该学号，本次新加入 |
| 更新/去重 M 行 | 学号已存在，按本次名单更新了姓名（不新增记录） |
| 跳过 Y 行 | 首个可解析行之后无法解析的非空行（题头/表头与空行不计入） |
| 跳过示例 | 最多列出 3 条被跳过的原行，供排查格式 |
| 编码识别 | 实际使用的读取方式：文本为 UTF-8 / GB18030；Excel 文件显示 `Excel(.xlsx)` / `Excel(.xls)` |

📷 截图占位 2：导入结果弹窗（含跳过示例）

### 2.3 乱码 / 跳过行排查

- 跳过行的常见原因：该行没有 10 位学号 / 学号位数不对 / 一行挤了多个人。对照「跳过示例」修正源文件后**重新导入**即可（重复导入安全）。
- 名单文本本身乱码：系统会自动在 UTF-8 / GB18030 之间识别；若「编码识别」一栏显示 `ISO-8859-1` 且姓名乱码，请用记事本把名单另存为 **UTF-8** 后重新导入。
- 想试玩：用仓库自带样例 `samples/名单样例-规整.txt`（预期：成功 8 行 / 跳过 0）。

## 3. 候选人列表与搜索

左侧导航点「**候选人**」：

- 顶部**常驻搜索框**：输入姓名（部分即可）或学号（可只输前几位）→ 回车或点「搜索」；**留空搜索 = 显示全部**。
- 表格列：学号 / 姓名 / **状态徽标** / 完成时间。

### 3.1 状态徽标含义

| 徽标颜色 | 状态 | 含义 |
|---|---|---|
| 🟡 黄色 | 未面试 | 已导入名单，尚未开始面试 |
| 🔵 蓝色 | 面试中 | 正在面试打分（同一时刻全系统最多 1 人；中途退出也保持此状态） |
| 🟢 绿色 | 已结束面试 | 已完成评分结算，产生了最终分 |

### 3.2 恢复未完成面试

- 启动时若有「面试中」的人，会弹窗询问是否继续；
- 平时也可在**仪表盘**的黄色提示卡中点「继续该面试 →」，或直接点「面试打分」页——只要存在面试中的人，该页会自动进入此人的打分界面。

### 3.3 名单管理（二期新增）

列表页底部的「**名单管理**」卡（候选人明细页右侧也有同样一组）提供手工增删改：

| 操作 | 用法 | 说明 |
|---|---|---|
| 新增候选人 | 填姓名 + 10 位学号 → 「新增候选人」 | 姓名须为 2~64 个汉字（`·` 连接）；学号不能与已有重复 |
| 改名 | 选中一行 → 填新姓名 → 「改名」 | 任意状态允许 |
| 改学号 | 选中一行 → 填新学号 → 「改学号」 | 会弹确认框：该人的**四维评分/附加分/操作日志一并迁移**到新学号；「面试中」不可改 |
| 删除 | 选中一行 → 「删除该候选人」 | 红色按钮；会弹确认框：**级联删除**其全部评分/附加/日志，不可撤销；「面试中」不可删 |

增删改后列表、明细与仪表盘统计会自动刷新。

## 4. 面试打分界面

左侧导航点「**面试打分**」：

1. **选人视图**：搜索或在列表中选中一位「未面试」候选人 → 点「**开始面试**」。
   - 若已有人在面试中，本页会直接显示该人的打分界面（同一时刻只能面试一人）；此时开始对他人面试会被拒绝并提示原因。
2. **打分界面（二期：四维评分）**：
   - 上方卡片显示候选人姓名/学号/状态与已录「四维评分记录 N 条」；
   - 中间表格列出已录入的每一条评分记录（序号/**责任心/时间管理能力/学生工作能力/部门契合度**/录入时间）；
   - 底部为**四个输入框**（中文标签同表格列），**每一维 0~25、最多两位小数**；回车自动跳到下一维，
     最后一维回车或点「**保存评分**」提交。**每保存一条立即入库**，下方绿色「✓ 已保存第 N 条四维评分…」
     提示含四个维度的值，可连续打分。

### 4.1 误输入处理

- 点「**删除上一条（误输入）**」→ 确认后删除最近一条四维评分（提示会列出被删的四个维度值）；
- 删错了也不要紧：到「撤销」页可以恢复（见第 6 节）。

### 4.2 结束评分（重要）

点「**结束评分并计算最终分**」：

- **已有 ≥3 条记录**：四个维度**各自**「去掉 1 个最高分、1 个最低分」取平均，直接弹出结算结果；
- **只有 1~2 条记录**：弹出「**评分不足 3 条 — 二次确认**」对话框，说明四个维度将各自按**普通平均**
  计算（列出每维的平均值与四维合计、最终分）——
  - 点「确定」= 按普通平均结束面试；
  - 点「取消」= 不结束，回到打分界面继续添加评分；
- **0 条记录**：不允许结束（会提示先录入至少 1 条完整评分）。

📷 截图占位 4：「评分不足 3 条」二次确认弹窗

### 4.3 结算结果弹窗

结束评分后展示：**四个维度的平均分**（责任心均/时间管理能力均/学生工作能力均/部门契合度均）、
**四维合计**（含计算方式：去极值平均/普通平均）、**附加分合计**、**最终分**。
最终分 = 四维合计 + 附加分合计（四维合计 ≤100；附加分单笔 ≤10、可多笔无总上限）。

📷 截图占位 5：结束评分结算结果弹窗

### 4.4 中途离开

直接点左侧其它页面即可（或「暂存返回」按钮）——该候选人保持「面试中」，已录评分全部保留，下次回来接着打。

## 5. 补录 / 附加分表单

在「候选人」列表**双击**某位候选人（或在排名页双击某一行）→ 进入「**候选人明细**」页：

- 左侧：候选人信息卡、**四维评分记录表**（序号/四维/录入时间）、附加分表、
  汇总卡（**四个维度平均**/四维合计/平均方式/附加分合计/**最终分**，未结束面试显示「未确定」）；
- 右侧三个操作组：补录表单、附加分表单、**名单管理**（见 3.3）。

### 5.1 补录四维评分（仅「已结束面试」可用）

- 适用场景：面试结束后发现漏录了一条评分。
- 填**四个维度**（各 0~25，最多两位小数）→ 点「补录」→ 提示「✓ 补录成功」，**最终分立即按最新明细整体重算**
  （每维重新去极值；补录后仍不足 3 条按各维普通平均口径）。
- 若该候选人**未面试**或**面试中**，四个输入框与按钮会置灰并显示原因（面试中的人请直接在「面试打分」页添加评分）。

### 5.2 附加分（任意状态可加）

- 适用场景：才艺、比赛、展示等加分。
- 填「附加分值」(**单笔 0~10**，可加多笔、无总上限) +「**加分原因（必填）**」→ 点「添加附加分」→
  提示「✓ 附加成功」，汇总卡同步刷新；输入 0~10 之外的值（如 11）会被即时拦截提示；
- 原因必填（≤200 字），不填会被拒绝；
- 附加分**不参与**四维去极值平均，直接并入最终分；一人可加多笔，逐笔列示；未结束面试者到「结束评分」时计入。

## 6. 撤销界面

左侧导航点「**撤销**」：

- 页面显示「**最近一次可撤销操作**」的预览（谁、什么操作、分值、时间），如「给 张三（2023000001）添加普通评分 85.50」；
- 点「撤销该操作」→ 二次确认 → 显示撤销结果：该候选人剩余评分条数；若其已结束面试，同时显示**撤销后的最新最终分**；
- **支持连续撤销**：撤销后页面会刷新出「下一条」可撤销操作，可一直撤到本批记录起点；
- **没有任何可撤销操作时**，按钮置灰并提示。

### 6.1 撤销边界（系统会拒绝并解释的情况）

| 提示 | 原因与处理 |
|---|---|
| 「不能撤销该操作：候选人 X 已结束面试且只剩这一条评分…」 | 撤销会让已结束者评分变 0 条、无法计算最终分。改用「补录/附加」修正，或初始化后重新面试 |
| 「没有任何可撤销的评分操作。」 | 日志为空（可能刚初始化过，或已全部撤完）——撤销**不能跨过初始化** |

只有「评分类」操作可撤销（打分/补录/删除评分/附加分）；导入、结束面试、初始化本身不可撤销。

## 7. 排名与导出

左侧导航点「**排名**」：

- **排名表**：仅「已结束面试」的人参与；列：名次/姓名/学号/**责任心均/时间管理能力均/学生工作能力均/部门契合度均/四维合计**/平均方式/附加合计/最终分/记录数；
- **排序规则（声明）**：最终分**降序** → 最终分相同**逐维比较**四维平均（责任心 → 时间管理能力 → 学生工作能力 → 部门契合度）→ 仍同分按**学号升序**——名次唯一、无并列；
- **未完成面试区**：页面下方单独列出「未面试/面试中」的人，不占用名次；
- 双击排名表的某一行可跳到该人明细页。

### 7.1 导出 CSV

点「**导出 CSV…**」→ 先选范围（单选）：

- **仅已完成**：正式排名结果；
- **全部（含未完成）**：未完成者排在末尾、名次与分数留空但明细保留，**适合备份**。

再选择保存位置（默认文件名 `导出_年月日_时分秒.csv`）→ 成功后提示导出行数。

- 列序（二期）：排名/学号/姓名/四个维度/四维合计/平均方式/评分记录数/**附加分明细（分值(理由)）**/附加分合计/最终分；
- 文件为 **UTF-8 带 BOM**，用 Excel **双击直接打开不会乱码**；
- **备份建议**：重要节点（如一轮面试结束、初始化前）都导出一份「全部」范围 CSV 存档。

## 8. 初始化系统 与 彻底重置（两个不同的危险操作，务必分清）

### 8.1 初始化系统（保留名单）

左侧导航「**初始化系统**」（红字描边样式）。用于清空全部评分、重新开始（如新一轮纳新）。防护流程与 CLI 完全同级（《接口文档》§8.4）：

1. **第 1 步 · 风险提示**：弹出当前数据统计（将清空 X 条四维评分记录、Y 条附加分、N 名候选人回到未面试；**名单保留**）→ 确认「是否继续」；
2. **第 2 步 · 备份建议**：询问是否**先导出备份 CSV**（建议选「全部」范围，未完成者的已录明细也可留档）——可选「先导出备份 / 跳过备份 / 取消初始化」；
3. **第 3 步 · 二次确认**：弹出输入框，**必须手工输入 `YES`**（不区分大小写）才能点「确认初始化」；其它任何输入都视为取消；
4. 执行后：全部评分、附加分、撤销日志清空，所有候选人回到「未面试」；**候选人名单保留**。

> ⚠ 初始化**不可恢复、不可撤销**（撤销日志也会被清空）。务必先备份。

### 8.2 彻底重置（删除一切数据，红色实底按钮）

左侧导航底部的**红色实底按钮「彻底重置（删除一切数据）」**——比初始化更彻底：
**候选人名单也一并删除**，数据库文件与 `data/` 下导出/备份 CSV 全部删除并原地重建空库（《接口文档》§8.6）：

1. **第 1 步 · 文件清单预览**：对话框列出将被删除的每一个文件（数据库/伴生文件/数据目录 CSV）
   与统计风险（名单 N 人、四维评分记录 N 条、附加分 N 条）；
2. **第 2 步 · 备份建议**：可选「先导出留档」（范围=全部；这是彻底重置前最后的挽救机会）；
3. **第 3 步 · 第一次确认**：普通确认框，明示与「初始化系统」的区别；
4. **第 4 步 · 最终确认**：输入框**必须手工输入 `彻底重置`** 四个字（区别于初始化的 YES，防止手滑混淆）
   才能点「确认彻底重置」；
5. 执行后弹窗列出**已删除的文件**；界面回到全新空状态（仪表盘归零、列表/排名清空），可直接重新导入名单或用「名单管理」手工新增。

> ⚠⚠ 彻底重置**删除一切数据且不可恢复**——比初始化更危险，请确认真的不再需要任何数据。

## 9. 数据文件位置、备份/迁移、与 CLI 共用数据库

| 项 | 位置 / 方法 |
|---|---|
| 数据库文件 | 程序根目录 `data/scoring.mv.db`（H2 嵌入式单文件库，无需安装数据库服务） |
| 一期旧库升级 | 二期程序首次打开一期旧库会**自动迁移**并弹提示（旧单值评分不换算进四维，明细请以一期导出的 CSV 为准） |
| 导出/备份 CSV | 由「导出 CSV」/ 初始化与彻底重置向导中的保存对话框自选位置（默认建议放 `data/`） |
| 备份整个系统数据 | 关闭程序后，复制 `data/scoring.mv.db` 一个文件即可 |
| 迁移到另一台电脑 | 把项目文件夹连同 `data/scoring.mv.db` 一起拷贝；新机器装好 JDK 17 并按第 1 节准备组件即可启动 |
| 更换数据库位置 | 设环境变量 `SCORING_DB_URL=jdbc:h2:file:路径/scoring`（一般不需要） |

### 9.1 与 CLI 版共用同一数据库

- GUI 版与 CLI 版读写的是**同一个** `data/scoring.mv.db`：在 CLI 里导入的名单、打的分，打开 GUI 立刻可见，反之亦然；
- **但同一时刻只能运行其中一个程序**（单进程单实例）：先完全退出一个，再开另一个，否则后者会因数据库被占用而打不开（会弹出提示）。

## 10. 常见问题（FAQ）

| 问题 | 处理 |
|---|---|
| 双击 `run-gui.bat` 没反应/报错找不到 java | 安装 JDK 17 并确认命令行 `java -version` 显示 17.x |
| 提示「缺少 JavaFX SDK / 缺少 H2 驱动」 | 按第 1 节顺序先跑 `fetch-libs` 与 `fetch-gui-libs`（需联网一次），再 `build-gui` |
| 提示「无法打开数据库…没有其它程序正在使用同一数据库」 | 已有 CLI 或另一个 GUI 在运行：先退出它再启动（见 9.1） |
| 启动弹出「旧库已自动迁移」 | 一期旧库首次被二期程序打开的正常提示；旧单值评分不换算进四维，历史明细请以一期导出的 CSV 为准 |
| 导入 xlsx/xls 没反应或报编码 | 确认文件未被 Excel 独占打开；程序按文件内容自动识别 Excel，导入结果「编码识别」会显示 `Excel(.xlsx/.xls)` |
| 附加分输入 11 提示「需在 0~10 之间」 | 二期起附加分**单笔上限 10**；需要更高就把加分拆成多笔（各自 ≤10、原因必填） |
| 四维分值输不进去（提示 0~25） | 每一维上限 25、两位小数；四个框回车自动跳下一维，最后一维回车即保存 |
| 「名单管理」按钮是灰的 | 改名/改学号/删除需要**先在表格中选中一行**；面试中的人禁止改学号与删除（先结束面试） |
| 导入后有人没进名单 | 看导入结果里的「跳过示例」：多为该行没有恰好 10 位数字学号，或一行挤了多人；修正后重新导入（安全） |
| 名单姓名是「阿依古丽 买买提」（空格）被截短 | 改成 `阿依古丽·买买提`（间隔号 `·`）后重新导入；重复导入只会更新姓名 |
| 导出的 CSV 在 Excel 里乱码 | 本系统导出已带 BOM，正常双击不乱码；个别旧版 Excel 请用「数据 → 从文本/CSV 导入 → 编码选 UTF-8」 |
| 忘记数据库/导出文件在哪 | 数据库在程序根目录 `data/scoring.mv.db`；导出文件保存在你导出时选择的位置（默认建议 `data/`） |
| 窗口里中文/界面显示异常 | 确认 `chcp 65001`（Windows 控制台）；系统需装有中文字体（Windows 默认有） |
| 想清空全部评分重来 | 保留名单用「初始化系统」；连名单一起清空用「彻底重置」（第 8 节），操作前务必备份 |
